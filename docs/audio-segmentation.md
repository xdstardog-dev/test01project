# 800ms 音频断句可行性与最小改动方案

状态：仅完成现有方案核查和 UI 状态精简；尚未接入 VAD，未实现 800ms 断句，也未更换 ASR 服务。

## 当前实现

`src/browserAsr.ts` 使用浏览器 `SpeechRecognition` / `webkitSpeechRecognition`，启用 `zh-CN`、`continuous` 和 `interimResults`。同一会话的结果索引对应同一字幕 ID，由 `isFinal` 启动字幕生命周期。

Web Speech API 没有可设置的尾部静音毫秒数。`speechend` 是识别器已经判断语音结束后的通知，不提供其内部判定阈值。当前事件只给出文本、结果索引和 Final 状态，没有词级音频时间戳或我们指定的音频片段 ID。不能从“文字没有更新”推断“用户没有说话”。

单独增加一个 800ms JavaScript 定时器不满足要求。即使通过真实音频测得静音，当前识别器也可能在之后返回同时包含两个发言片段的一条结果；按字符串前缀剪切会在识别修订、重复词、同音词更正时丢字或重复。`stop()` 后等待 Final 再 `start()` 会产生识别空档；`abort()` 可能丢弃尚未返回的结果。

现有会话结束逻辑还会清除未确认 Interim，且连续两次无结果重连后停止。这些保护机制不能被描述成“麦克风无限持续”和“保证不丢字”。在支持片段关联的新链路完成前，保持现有行为，避免把未确认识别强行冒充准确的 Final。

参考：[接口与属性](https://webaudio.github.io/web-speech-api/#speechreco-section)、[stop 方法](https://webaudio.github.io/web-speech-api/#dom-speechrecognition-stop)、[speechend 事件](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/speechend_event)。

## 最小改动边界

保留房间、卡片、模拟模式、字体层级、布局、滚动和 3/6/10 秒＋2 秒渐隐；变动集中在音频采集/识别适配器和字幕结果更新接口。

1. 使用 `getUserMedia` 持续持有同一条麦克风音轨，由 AudioWorklet 按音频帧采样，接独立 VAD。应基于语音概率和噪声校准判断语音，而不是把简单音量阈值等同于可靠 VAD。
2. 以音频采样位置计算连续非语音时长；达到 800ms 才封闭片段。0.3 秒和 0.6 秒停顿重置静音累计并继续当前片段，0.9 秒停顿应在约 0.8 秒时封闭。实际时间精度受音频帧长度和 VAD 误判影响，不承诺任意环境下逐毫秒准确。
3. 采集不中断，维护有界音频缓冲及单调递增 segmentId。每个片段的音频必须能绑定到其 ASR 请求或具有可对齐的结果时间戳；下一片段不能等待上一片段的迟到 Final 才开始采集。
4. 静音边界到达时保留当前临时文本，以同一 ID 提交显示并启动生命周期，另记“服务最终结果仍待确认”。迟到 Final 仅修订对应片段，不能追加重复消息、覆盖下一段或重置原计时。若没有临时文本，则保留有界的待识别片段，结果到达后首次显示。已经过期的字幕不重新出现。
5. 字幕生命周期与服务确认状态分离；当前 `receiveCaption()` 会忽略已有 Final 的修订，需要只针对同一 segmentId 增加明确的修订入口，不影响现有重复 Final 防护和模拟逻辑。超时、错误和队列上限必须明确反馈，不能静默丢弃未处理音频。
6. 关闭/离房时停止音轨、AudioWorklet、VAD 与传输，并释放缓冲；片段边界本身不关闭麦克风。

## 是否必须更换服务

可以先只增加本地 VAD，保留当前 Web Speech API，用来验证“800ms 静音边界”检测，但这只是检测实验，不能可靠实现上述片段和迟到 Final 的一一对应。

部分浏览器提供 `start(audioTrack)`，可进一步评估受控音轨及缓冲重放；支持范围有限，不能假定所有当前支持的浏览器都能使用，也不能在未验证之前承诺无缝分段。参见 [start(audioTrack)](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/start)。

若要求完整满足“800ms 分段、持续采集、迟到 Final 正确归属”，建议在现有适配器之外增加能够接收应用音频流、关联片段的 ASR 后端。800ms 规则由独立 VAD 决定，识别服务负责转写。服务选择、兼容性、密钥部署及费用需要先给出具体方案并获得用户确认；当前不创建账户、不接收费服务、不在前端放服务端密钥。
